## 必须遵循的最佳实践和规则：

- 技术栈：
  - fastapi
  - sqlmodel
- 使用 uv 进行依赖管理工具


1. **使用有意义的命名**：选择描述性强的变量、函数和类名。
2. **遵循 PEP 8 规范**：遵守 Python 增强提案 8 的代码格式指南。
3. **编写文档字符串**：使用文档字符串说明函数和类的用途。
4. **保持简洁性**：编写简单清晰的代码，避免不必要的复杂性。
5. **优先使用列表推导式**：在适当场景下，优先使用列表推导式而非传统循环创建列表。
6. **异常处理**：使用 try-except 块优雅地处理异常。
7. **使用虚拟环境**：通过虚拟环境（如 `venv`）隔离项目依赖。
8. **编写测试用例**：实现单元测试以确保代码可靠性。
9. **类型注解**：使用类型提示增强代码可读性和类型检查。
10. **避免全局变量**：减少全局变量的使用以降低副作用风险。

## 项目结构

- Project/
  - app/: fasteapi 应用目录
    - api/: 存放API路由
      - routes/: 存放具体的路由文件，每个模块要以包的形式
    - constant: 常量文件
    - core: 核心功能，如配置、数据库连接等
    - email-templates/: 邮件模板
    - models/: 数据库模型
    - tests/: 单元测试目录
    - utils/: 工具函数
    - main.py: 入口文件
    - backend_pre_start.py: 部署时的预启动脚本
    - initial_data.py: 初始化数据脚本
    - lifespan.py: fastapi 应用生命周期管理
    - tests_pre_start.py: 测试时的预启动脚本
  - db/: 数据库模型和迁移文件，主要是sqlite数据库
  - doc/: 文档目录
    - ai/: 用于AI辅助编码的文档
  - scripts/: 脚本目录
  - .env: 环境变量配置文件
  - README.md: 项目说明文档
  - release_notes.md: 发布说明
